## 6. Rollback Procedures

If an issue is detected during or after production promotion:

### 6.1 Rollback Before PR Merge (Current State)
- Simply close the PR on GitHub without merging.
- Local `development` and `main` branches remain completely unaffected.

### 6.2 Rollback After PR Merge on `main`
If the PR has been merged into `main` and a critical defect is identified:
1. Revert the merge commit on `main`:
   ```powershell
   git checkout main
   git pull origin main
   git revert -m 1 <MERGE_COMMIT_HASH> -m "revert: rollback v0.18.0 release from production"
   git push origin main
   ```
2. Notify users on the GitHub Release page by marking `v0.18.0` as pre-release or appending a known-issue notice.

### 6.3 Store Submission Rollback
- **Firefox AMO:** Rollback to previously approved version (`v0.16.0` or `v0.17.0`) via the version management dashboard, or cancel pending review.
- **Chrome Web Store:** Cancel the pending review in Chrome Developer Dashboard before approval, or upload a patch package (`v0.18.1`) immediately.
