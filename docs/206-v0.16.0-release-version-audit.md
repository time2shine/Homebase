## 3. Changes Since v0.15.0

Across **68 commits** since `v0.15.0`, the Homebase repository underwent a comprehensive architectural overhaul, stability hardening, observability integration, and testing modernization:

### 3.1 Major Subsystems & Features Added
1. **Schema Versioning & Migration Engine (`schema-migrations.js`):**
   - Introduced persistent schema tracking (`CURRENT_SCHEMA_VERSION = 1`).
   - Implemented automated schema upgrades, backward-compatibility shims, and future-version protection.
2. **Storage Validation & Sanitization Architecture (`schema-validator.js`):**
   - Implemented strict key whitelisting for all 70+ storage keys.
   - Guarded against prototype pollution (`__proto__`, `constructor`, `prototype`).
   - Enforced type checking and range clamping on all persisted preferences.
3. **Storage Health Observability Engine (`storage-diagnostics.js`):**
   - Real-time diagnostics assessing storage integrity, key count, corruption detection, and schema alignment.
   - Built zero-leak privacy guarantees: diagnostics inspect structural metadata only without exposing personal bookmark or note data.
4. **Interactive Storage Diagnostic HUD Panel (`diagnostic-ui.js`):**
   - Added user-facing Storage Health & Diagnostics UI in Settings.
   - Diagnostic status indicator (Healthy, Degraded, Critical).
   - In-app repair workflows and structured diagnostic report export.
5. **Transactional Backup Engine (`backup-import.js`):**
   - Atomic multi-key import with rollback protection.
   - Strict payload validation and custom wallpaper asset deduplication.
6. **Native 4-Stage Test Suite (`scripts/test.mjs`):**
   - 367 automated unit and integration tests executing natively on `node:test` in under 3 seconds.
   - Static invariant validation (`check-newtab-static.mjs`) guarding against global declaration collisions.
   - Real headless browser smoke verification (`smoke-newtab-file.mjs`).

### 3.2 Monolith Decomposition & Architecture Extraction
`src/new-tab.js` was refactored from a 13,800-line monolith down to 1,799 lines (87% reduction). Over 25 modular first-party controllers and services were extracted into `src/newtab/`:
- **Unified Storage Facade:** `HomebaseStorage`, `HostStorageAdapter`, and `StorageDispatcher`.
- **Bookmarks Subsystem:** `bookmark-grid-controller.js`, `bookmark-action-controller.js`, `bookmark-root-controller.js`, `bookmark-loader-service.js`, `bookmark-tree-service.js`, `bookmark-ui-state.js`, `bookmark-editor-adapter.js`, and `bookmark-storage.js`.
- **Search Subsystem:** `search-interaction-controller.js`, `search-ui-controller.js`, and `search-storage.js`.
- **Wallpaper Subsystem:** `wallpaper-controller.js`, `wallpaper-storage.js`, asset caching pipeline, rotation runtime, and video playback lifecycle.
- **Core & UI Runtime:** `favicon-pipeline.js`, `context-menu-controller.js`, `dialog-controller.js`, `asset-loader.js`, and `performance-controller.js`.

### 3.3 Bug Fixes & Resilience
- **Global Scope Clashing:** Resolved duplicate lexical declaration risk in `<script defer>` execution using static declaration scanners.
- **Bookmark Renaming Synchronization:** Fixed desync between grid title renames and edit dialog caches.
- **Sidebar Ordering:** Fixed variable reference error in widget visibility ordering during instant start.
- **Weather Resilience:** Added defensive fallbacks for Open-Meteo network failures and non-JSON responses.

### 3.4 Backward Compatibility & Permissions
- **100% Backward Compatible:** All existing bookmarks, settings, and custom wallpapers remain intact.
- **Zero Permission Changes:** No new browser permissions or host permissions were introduced in Chrome or Firefox manifests.

## 4. Recommended New Version

### Recommendation: **`v0.16.0` (Minor Version Bump)**

### Semantic Versioning Rationale (SemVer 2.0.0):
1. **Scope of Additions (`0.Y.0`):** In pre-1.0 software development (`0.y.z`), a minor version bump (`Y`) signifies substantial new functionality, significant architectural transformations, new subsystems, and major internal refactoring executed without breaking backward compatibility.
2. **Why Not a Patch (`0.15.1`)?**
   - 68 commits ahead of the last release.
   - An 87% monolith reduction (13,800 -> 1,799 lines).
   - Entirely new subsystems: Schema Migrations, Observability Engine, Diagnostic HUD, Transactional Backup Engine, and 367 automated tests.
   - Labeling this landmark release as a patch (0.15.1) would severely mischaracterize the scope and magnitude of engineering achievements.
3. **Why Not Major (`1.0.0`)?**
   - SemVer conventions reserve `1.0.0` for a formal, finalized public API contract milestone. Homebase remains under active iterative evolution within the `0.x` series.
   - All user data and storage formats remain 100% backward compatible without breaking changes.
4. **Conclusion:** **`v0.16.0`** is the standard, technically accurate, and semantically sound version designation.
