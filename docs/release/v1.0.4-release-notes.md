## 1. Release Executive Summary

**Homebase v1.0.4** is a major accessibility, keyboard navigation, and storage reliability release. It introduces WAI-ARIA 1.2 combobox and listbox semantics to the search dashboard, provides fully accessible keyboard navigation for the search engine selector in Microsoft Edge and Mozilla Firefox, implements keyboard activation and visible focus for bookmarks and folders, adds robust modal focus management and nested dialog isolation to Settings, and resolves cross-browser backup import verification failures caused by Chromium LevelDB key serialization.

Key updates in this release:
1. **Search Combobox & Accessible Suggestions**: Transformed `#search-input` into an accessible combobox (`role="combobox"`, `aria-autocomplete="list"`, `aria-expanded`, `aria-controls`) and `#search-results-panel` into a categorized listbox (`role="listbox"`, `role="group"`). Results receive `role="option"` with unique monotonic IDs, synchronized `aria-activedescendant`, and focus retained in the input. Migrated category jumping to unmodified `PageDown`/`PageUp` so `Tab` and `Shift+Tab` exit the popup normally. Calculator results communicate their copy action accessibly without nested interactive tab stops.
2. **Search Engine Selector Keyboard Access (Edge & Firefox)**: Added complete keyboard accessibility to `#search-engine-selector` in Edge and Firefox using native buttons, `role="group"`, and roving tabindex (`tabindex="0"` on the active engine). Focusing the selector (`:focus-within`) smoothly expands the list with high-contrast `:focus-visible` outlines without layout shifts. Unmodified `ArrowRight`/`ArrowLeft` and `Home`/`End` navigate engines with boundary wrapping, while modifier keys (`Alt`, `Ctrl`, `Meta`, `Shift`) pass through unintercepted, preserving global shortcuts (`Alt+Home` default reset, `Alt+ArrowUp/Down` engine cycling). Enter and Space activate the focused engine exactly once; Escape cancels and returns focus to the search input.
3. **Chrome Distribution Isolation**: In Chrome builds, browser-default search remains strictly isolated. The search engine selector is emptied and hidden (`display: none`, `aria-hidden="true"`), omitted from the accessibility tree and tab order, and the search input retains neutral labels (`"Search the web"`).
4. **Bookmark & Folder Keyboard Navigation**: Enabled keyboard navigation for bookmark and folder tiles on the virtual grid. Bookmark tiles receive `role="link"` and activate on Enter with target preferences and Firefox container tab support. Folder and Back tiles receive `role="button"` and activate on Enter or Space, with held-key duplicate suppression (`e.repeat`) and scroll prevention. Added high-contrast `:focus-visible` outlines (`2px solid #2ca5ff; outline-offset: 2px`) with zero layout shift. Nested interactive controls and inline rename inputs are excluded, and recycled virtual DOM nodes blur safely when their identity changes under focus.
5. **Settings Focus Containment & Nested Isolation**: Transformed `#app-settings-dialog` into an accessible modal dialog (`role="dialog"`, `aria-modal="true"`, `aria-labelledby="app-settings-title"`). Implemented dynamic focus trapping for `Tab` and `Shift+Tab`, excluding hidden sections, hidden footers, and disabled controls. Saved opener elements are safely restored upon dialog closure. Nested modal dialogs (Search Engines, Animation Settings, Glass Settings, Folder Picker) isolate Escape handling, preventing premature Settings dialog closure while maintaining transactional discard on Settings Escape. Rescued focus to section navigation buttons when the active control is hidden by section switching.
6. **Backup Import Verification & Key Ordering**: Storage writes during backup import now treat `writeResult.rejectedKeys` as transaction failures alongside write errors, immediately triggering rollback. Replaced `JSON.stringify` comparison with deep recursive order-independent equality validation in `areValuesIdentical` and `computeStorageDelta`, preventing Chromium's LevelDB storage (`base::Value::Dict` alphabetical key sorting) from triggering false delta writes or verification failures on identical object settings (e.g. `wallpaperSelection`). Clarified backup UI copy regarding what settings are restored versus excluded.

## 2. Issues Resolved

### 2.1 Search Suggestion & Engine Selector Keyboard Accessibility
- **Issue**: The search input and suggestions panel lacked ARIA semantics, preventing screen readers from announcing suggestions, active options, or combobox state. Tabbing into the search panel trapped focus or cycled categories instead of exiting. In Edge and Firefox, the search engine selector was mouse-only.
- **Resolution**:
  - Assigned `role="combobox"`, `aria-expanded`, and `aria-controls` to `#search-input`; assigned `role="listbox"` to `#search-results-panel` and `role="group"` to suggestion categories.
  - Assigned `role="option"` with unique monotonic IDs (`search-result-opt-...`) to all results; synchronized `aria-activedescendant` during keyboard navigation while keeping DOM focus in `#search-input`.
  - Migrated category jumping to unmodified `PageDown`/`PageUp`; allowed `Tab` and `Shift+Tab` to dismiss results and exit naturally.
  - Implemented roving tabindex, arrow navigation, boundary wrapping, and `:focus-within` expansion on `#search-engine-selector` in Edge and Firefox.
  - Bypassed modifier keys (`Alt`, `Ctrl`, `Meta`, `Shift`) in selector keydown handling, preserving global shortcuts (`Alt+Home`, `Alt+ArrowUp/Down`) and browser navigation.
  - Preserved Chrome distribution isolation where the selector is completely hidden and searches route directly to the default provider.

### 2.2 Bookmark & Folder Keyboard Navigation & Focus
- **Issue**: Bookmark and folder tiles on the virtual grid could not be activated using the keyboard, lacked link/button roles, and displayed inconsistent or shifted focus outlines. Virtual node recycling could leave focus stranded or jump unexpectedly.
- **Resolution**:
  - Assigned `role="link"` and `tabindex="0"` to bookmark tiles, activating on Enter with target preferences and container tab support.
  - Assigned `role="button"` and `tabindex="0"` to folder and Back tiles, activating on Enter and Space with held-key duplicate suppression (`e.repeat`).
  - Added high-contrast `:focus-visible` styling (`outline: 2px solid #2ca5ff; outline-offset: 2px`) without border or margin layout shift.
  - Excluded nested interactive controls (`input`, `textarea`, `button`, `select`, `a`, contenteditable, rename inputs) from tile activation.
  - Blurred recycled virtual nodes (`el.blur()`) when their bound bookmark ID changes while focused, preventing focus jumps.

### 2.3 Settings Dialog Focus Management & Nested Isolation
- **Issue**: The Settings modal lacked dialog semantics and focus containment. Pressing Tab allowed focus to escape behind the dialog into the dashboard, pressing Escape in a nested dialog closed the parent Settings modal, and closing Settings dropped focus to `document.body`.
- **Resolution**:
  - Assigned `role="dialog"`, `aria-modal="true"`, `aria-labelledby="app-settings-title"`, and `tabindex="-1"` to `#app-settings-dialog`.
  - Implemented dynamic focus trap for `Tab` and `Shift+Tab`, filtering inactive sections, hidden footers, and disabled controls.
  - Captured opener elements and restored focus to the invoking button upon close, with sequence token validation to prevent stale callbacks from stealing focus.
  - Isolated Escape events in nested modals (`search-engines-modal`, `animation-settings-modal`, `glass-settings-modal`, `folder-picker-modal`), preventing Settings from closing prematurely while preserving transactional rollback on Settings Escape.
  - Rescued focus to the active section navigation button when switching sections deactivates the currently focused control.

### 2.4 Backup Import Verification & Cross-Browser Key Ordering
- **Issue**: Importing a valid backup in Chromium browsers could falsely fail verification and roll back because Chromium's LevelDB storage engine serializes dictionary keys in alphabetical order, causing naive `JSON.stringify` comparison to report differences for identical object values. Furthermore, partial write rejections were not treated as transaction failures.
- **Resolution**:
  - Treated `writeResult.rejectedKeys` as transaction failures alongside write errors, immediately invoking automated rollback.
  - Implemented deep recursive order-independent equality comparison for plain objects with circular reference defense in `areValuesIdentical` and `computeStorageDelta`.
  - Re-verified value equality on read-back against expected delta updates.
  - Clarified backup UI explanation regarding overwritten settings versus unchanged unbacked settings.
